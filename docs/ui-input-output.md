# UI input and output catalog

All pages use the shared landmark layout and skip link. Data pages are
server-rendered by default; interactive forms use focused client components.
UTC instants are formatted in `AGENTCLINIC_TIME_ZONE` (default
America/Sao_Paulo). No UI writes directly to SQLite.

Framework-level `app/loading.tsx` and `app/error.tsx` provide global pending and
retryable failure states. Segment loading/error/not-found files cover the
catalogs, dashboards and queue where present. A missing segment-specific error
boundary falls back to the nearest parent boundary.

## Workflows

### Catalog browsing and Ailment search

Visitors move from `/agents`, `/ailments`, or `/therapies` to details. Ailment
search submits `q`; the server trims it. Empty input behaves as an unfiltered
request. Clear removes the query. An empty array produces a no-results state,
not a 404.

### Availability and booking

Therapy detail lists only available, unblocked future slots. Selecting a slot
navigates to `/appointments/book?slotId=...`. The form requires name and email;
browser controls complement, but do not replace, server validation. Submission
uses a generated UUID idempotency key. New success navigates to the safe
confirmation route. A 409 presents stale/unavailable guidance rather than
claiming success.

### Authentication and session recovery

Sign-in sends email/password from a server action/client boundary to the API,
which sets session and CSRF cookies. Protected pages check the session and role.
Unauthenticated or expired sessions return to sign-in with a local return path;
wrong-role access uses `/forbidden`. Sign-out supplies Origin/cookie/CSRF and
clears state. Passwords, cookie values and tokens are never rendered.

### Agent cancellation

The Agent dashboard displays future confirmed appointments in ascending order.
The API supplies `cancellationEligible` and deadline; the UI does not recreate
the authority rule. Cancellation refreshes the displayed state. Ownership
mismatch and absent appointment are indistinguishable 404s; stale eligibility
is 409.

### Staff queue

Without filters, the queue shows future PENDING and CONFIRMED appointments.
Explicit filters control status, Agent, Therapy and a half-open time range.
Confirmation is available only for future PENDING records. Cancellation is
available for future active records and requires one approved operational
reason. Server response flags are authoritative. Visitor name/email are never
included in staff responses or rendered.

## Validation and accessibility

Server validation remains authoritative. Forms expose labels, keyboard
controls, visible errors/status feedback and predictable navigation. Loading,
empty, not-found, forbidden and retryable-error components use headings and
semantic status patterns tested by Testing Library and Playwright. Automated
axe checks exist for critical journeys; the Phase 12 manual NVDA review remains
pending and must not be inferred from automated coverage.

## Known UI ambiguity

- The legacy Agent dashboard route coexists with `/agent/dashboard`.
- There is no dedicated UI for readiness, backup, deployment or release.
- No pagination controls exist because APIs return complete collections.
- Browser validation details can vary by browser; API validation is the stable
  contract.
